2w2h 自述

收到 2w2h 的推送后打开：判这次用得对不对，不对怎么改。

  1. 它是什么：全机唯一黄金圈出页 skill
  2. 什么时候动：谁出页谁调它，调了就记、就推
  3. 不对怎么改：按第 4 段判据说一句

1WHY为什么要有它不做会怎样：每条线各写一套骨架、五个坑每次重踩、老徐不知道谁在用

先给结论：它管的不是「怎么把页做漂亮」，是三件「不做就会烂」的事。

  • 没有统一骨架 ⇒ 各写各的。 260824 老徐定「我们有且只有一套黄金圈，一切 html 都用黄金圈结构」。全机 HTML 里走了黄金圈的占多少，用时现算（见第 3 段），🚫 不写死 —— 老页迭代时才改，存量不回填，这是他定的
  • 没有 skill ⇒ 流程只活在 AI 的记忆里。 出页有六步、五个坑（生成器不能叫 _出页.py、变量不能叫 parts、注入要给 markdown……），每个坑都实撞过。写在文档里 AI 会忘，写成 skill 触发词一到就照步骤走
  • 没有推送 ⇒ 老徐不知道谁在用、用得对不对。 他 260904 原话：「我的目的是为了让自己知道什么在动、有什么问题，我得迭代」。推送不是留痕，是给他一个「打开本页 → 判 → 说一句改」的入口

⭐ 三件事是一件事：骨架保证出来的东西长一样，skill 保证每次都按同一条路出，推送保证出得不对时有人知道。

2HOW它靠什么做到出页是一份公共库，推送是一个挂在动作上的钩子，两者都不靠 AI 记得

先给结论：出页靠一份公共库，推送靠一个钩子；两样都是「挂在已经在跑的东西上」，不靠 AI 记得。

出页：三层管线，真身就在本夹
  • _md2html.py 把 markdown 渲染成 HTML 标签 → _出页.py 的 build_ring() 套上黄金圈骨架 → 各夹自己一份 20 行生成器只填标题、版本、注入
  • 🔴 ~/projects/OPC/格式标准 是一根软链接指到本夹（260904 整夹搬来）。全机生成器写死的旧路径一处没改、全接住。老徐的计划：跑顺了再改直接路径、撤软链接
  • 样式与脚本从样板原样抽（_抽出的* 三份，🚫 手改）；页内搜索、稳定锚 key=、动态工具条高度是出页器追加的 —— 所以 cp 模板.html 手写那条路拿不到这三样，本 skill 不走它
推送：挂在「Skill 被调用」这个硬事件上
  • Claude Code 每次调 Skill 工具后会跑 PostToolUse hook ⇒ ops/自动化/ai配置推送.py（~/.claude/hooks/ 里是软链接）
  • 它只认硬事件：① Skill 被调用（tool_name == Skill）② 被监视的文件真的变了（扫 mtime 跟快照比）。🚫 不猜「有没有用上某条 rule」—— 没有那个事件，猜就会假报
  • 节流按 kind 分：rule 10 分钟、skill 30 分钟（老徐 260904 晚定「用这个 skill 就 30 分钟内推送一次」）。窗口内压下的写进 pending，窗口一过的第一条推送全带出 —— 🔴 只压不攒会直接违背「知道什么在动」
  • 每次调用另记一行到 ~/.claude/.rs-notify/skill-usage.tsv，只追加不轮转，推送正文带「这个 skill 今日 N 次 · 累计 M 次」
  • 🕐 时间全打北京时间（老徐 260904 拍 B：云主机时区是纽约，不改系统，只这个脚本自己设 TZ）
3WHAT它产出什么 · 推送长什么样一页 HTML · 一行记录 · 一条推送，各自长什么样、去哪看

先给结论：三样产物：HTML 页、使用记录、推送消息。推送里 📖 文档 那行指向的就是本页。

4HOW GOOD怎么判它做得对不对 · 不对怎么改推送该不该来 · 这次该不该调 · 出的页对不对，三问各有判据；改只要一句话

先给结论：收到推送觉得不对，先分清是三类里的哪一类，再说一句「改 2w2h：……」。改的永远是三处之一：SKILL.md、本页 md、hook 脚本。

① 推送本身不合适（太频 · 太少 · 内容没用）
  • 判据：30 分钟内最多一条，压下的下条带出、不丢。频繁到烦 ⇒ 说「2w2h 推送窗口改成 60 分钟」；漏了 ⇒ 先看 ~/.claude/logs/rules-skills-notify.log 里是 stashed（在窗口里，正常）还是 postfail（发失败）
  • 内容没用 ⇒ 说清少了哪一行。🔴 但「推不出要改什么的东西一律不推」是那脚本的红线，别往里塞装饰
② 这次调用不该发生（那页不该出 HTML）
  • 判据（260823 老徐定）：md 正本管日常，HTML 管交付 —— 阶段性沟通完毕才出页；一个软件只有一份笔记别为它出页；别在子夹随手出 HTML
  • 看推送里 📂 在： 和 💬 参数： 就能判：是「谈完了出定稿」还是「边查边出」。后者 ⇒ 说「这页不该出，回 md」
③ 出来的页不对
  • 验收六样（scripts/验收.sh 一条命令）：字节数没倒退 · 四钮齐 · 每段有稳定锚 · 搜索框在 · 顶部产物标记 · 没有未填占位
  • 反例六条（结构输出标准.md）：同级标题平铺 · 按发现顺序排 · TL;DR 放最后 · 只有三档漏 HOW GOOD · 段落没 id · 展开先铺垫
  • 🔴 最常见的错是四档判错：WHY 写成功能清单（那是 WHAT）。判法只有一句：删掉这段，读者还知道「不做会怎样」吗？
怎么发起迭代

在 ops 项目开一条对话（或直接对 ops-claude 说），一句话：「改 2w2h：<上面①②③里的哪一条 ＋ 你看到的现象>」。 改完的那条线要重出本页（python3 _生成自述HTML.py），版本号加一、changelog 写一行 —— 🔴 本页就是 2w2h 的一部分，skill 变了页不变就是在骗人。

⭐ 今晚就能做的最小一步：跑一次上面那条 column -t 看使用记录，对一下跟你印象里「谁在出页」是否一致。
